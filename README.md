# MAX→TG Bridge

Мост сообщений **MAX → Telegram** для тех, у кого нет MAX.

Бот-приёмник состоит в вашей группе MAX (там же — ваш аккаунт) и читает каждое сообщение.
Фоновый воркер мгновенно пересылает его всем подписчикам Telegram-бота — **с именем и ником отправителя в MAX**.
Людям достаточно написать боту `/start`.

Плюс в комплекте: веб-панель с живым статусом, лентой сообщений, подписчиками и управлением пересылкой.

## Как это работает

```
Группа MAX ──(Bot API MAX, long polling)──> Воркер (Next.js на Railway)
                                                │  PostgreSQL: подписчики + лента
                                                v
                                   Telegram Bot API ──> личные сообщения подписчикам
```

- Long polling в обе стороны — **webhook и публичный домен не нужны** (на Railway выдаётся домен автоматически, мосту он не требуется).
- Мост стартует вместе с сервером через `src/instrumentation.ts`.
- Дубликаты отфильтровываются по `mid` сообщения MAX, маркер long polling хранится в БД.

## Команды Telegram-бота

| Команда  | Действие                                   |
| -------- | ------------------------------------------ |
| `/start` | Подписаться на пересылку (включить заново) |
| `/stop`  | Отписаться                                 |
| `/status`| Статус моста и число подписчиков           |
| `/help`  | Помощь                                     |

## Деплой на Railway

1. **Telegram-бот**: `@BotFather` → `/newbot` → скопируйте токен.
2. **Бот в MAX**: создайте бота на платформе MAX для партнёров ([dev.max.ru](https://dev.max.ru)), скопируйте токен, **добавьте бота в нужную группу MAX**.
3. Залейте этот репозиторий на GitHub → Railway → **New Project → Deploy from GitHub**.
4. Добавьте в проект **PostgreSQL** (Add → Database → PostgreSQL).
5. В Variables сервиса приложения задайте:

| Переменная           | Значение                                             |
| -------------------- | ---------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather                                   |
| `MAX_BOT_TOKEN`      | токен бота MAX                                       |
| `DATABASE_URL`       | `${{Postgres.DATABASE_URL}}` (ссылка на сервис БД)   |
| `ADMIN_SECRET`       | (опц.) пароль для веб-панели                          |
| `MAX_CHAT_ID`        | (опц.) chat_id группы MAX; пусто = все группы         |
| `MAX_API_BASE`       | (опц.) по умолчанию `https://platform-api2.max.ru`   |

6. Deploy. Таблицы создаются автоматически (`drizzle-kit push` в startCommand, см. `railway.toml`).
7. Напишите Telegram-боту `/start` — и пишите что-нибудь в группе MAX.

> Фильтр по группе удобно задать уже в веб-панели: как только бот попадёт в группу,
> её название и chat_id появятся в пульте — выберите её кликом.

## Веб-панель

Откройте домен Railway (`https://<project>.up.railway.app`):

- статус обоих ботов и воркера (пульс каждые 20 секунд);
- лента сообщений из MAX в реальном времени;
- список подписчиков (кого можно удалить);
- включение/выключение пересылки, фильтр группы, тестовая отправка.

Если задан `ADMIN_SECRET`, кнопки управления требуют ключ (вводится один раз, хранится в браузере).

## Локальная разработка

```bash
cp .env.example .env   # заполните токены
npm install
npx drizzle-kit push
npm run dev
```

Без токенов приложение тоже запустится — панель покажет подсказки по настройке.

## Структура

- `src/lib/max.ts` — клиент Bot API MAX (`/me`, `/updates`)
- `src/lib/telegram.ts` — клиент Telegram Bot API (long polling, sendMessage)
- `src/lib/bridge/` — воркер моста, обработка апдейтов, рассылка, хранение
- `src/instrumentation.ts` — автозапуск воркера при старте сервера
- `src/app/api/status` + `src/app/api/admin/*` — API панели
- `src/components/Dashboard.tsx` — пульт управления
