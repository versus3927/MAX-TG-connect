# MAX→TG Bridge

Мост сообщений **MAX → Telegram** для тех, у кого нет MAX.

Ваш **аккаунт MAX** состоит в группе — мост читает каждое сообщение от его лица
и мгновенно пересылает всем подписчикам Telegram-бота **с именем отправителя**.
Людям достаточно написать боту `/start`.

В комплекте — веб-панель: живой статус, лента сообщений, подписчики, включение/выключение
пересылки, выбор конкретной группы, тестовая отправка и подключение аккаунта по номеру телефона.

## Как это работает

```
Группа MAX ──(ваш аккаунт, WebSocket-протокол MAX)──> Воркер (Next.js на Railway)
                                                           │  PostgreSQL: подписчики + лента
                                                           v
                                        Telegram Bot API ──> личные сообщения подписчикам
```

- **Бот для MAX не нужен** — чтение идёт от вашего аккаунта (юзербот на приватном
  WebSocket-протоколе `wss://ws-api.oneme.ru/websocket`, ver=11, реверс-инжиниринг
  веб-клиента; см. [pr0bel1230/max-api-docs](https://github.com/pr0bel1230/max-api-docs)).
- Доставка: живые push-события + резервный опрос истории каждые 5 с (ни одно сообщение не потеряется).
- Дубликаты отфильтровываются по id сообщения, маркеры хранятся в БД.
- Webhook и публичный домен не нужны: Telegram — long polling, MAX — WebSocket.

## Важно про аккаунтный режим

Это **юзербот**: автоматизация личного аккаунта не предусмотрена официальным API MAX
и может нарушать условия сервиса — аккаунт теоретически могут ограничить.
Используйте отдельный аккаунт, если это критично.

- Подключение: в панели вводите номер телефона → код из SMS → токен сохраняется
  **только в памяти сервера** (в БД не пишется) и живёт до рестарта.
- После рестарта Railway подключите аккаунт ещё раз, либо задайте
  `MAX_ACCOUNT_TOKEN` (и опционально `MAX_DEVICE_ID`) — тогда вход автоматический.
- Иногда MAX просит VK-капчу перед SMS: тогда войдите один раз в
  [web.max.ru](https://web.max.ru) с компьютера и повторите запрос кода.

## Команды Telegram-бота

| Команда  | Действие                                   |
| -------- | ------------------------------------------ |
| `/start` | Подписаться на пересылку (включить заново) |
| `/stop`  | Отписаться                                 |
| `/status`| Статус моста и число подписчиков           |
| `/help`  | Помощь                                     |

## Деплой на Railway

1. **Telegram-бот**: `@BotFather` → `/newbot` → скопируйте токен.
2. Залейте репозиторий на GitHub → Railway → **New Project → Deploy from GitHub**.
3. Добавьте в проект **PostgreSQL** (Add → Database → PostgreSQL).
4. В Variables сервиса приложения задайте:

| Переменная           | Где взять                                                      |
| -------------------- | -------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | Telegram → **@BotFather** → `/newbot` (или `/mybots` → API Token) |
| `DATABASE_URL`       | Railway → Add → Database → PostgreSQL → значение `${{Postgres.DATABASE_URL}}` |
| `ADMIN_SECRET`       | Придумайте сами: длинная случайная строка. **Обязательно** — через панель выполняется вход в ваш MAX |
| `MAX_ACCOUNT_TOKEN`  | (опц.) Панель покажет токен один раз после SMS-входа — скопируйте, и вход станет автоматическим |
| `MAX_DEVICE_ID`      | (опц.) Любой UUID; пусто = сгенерируется                        |
| `MAX_CHAT_ID`        | (опц.) Панель → «Группа MAX»: после входа там появятся чаты с их chat_id — кликните нужную |
| `MAX_WS_URL`         | (опц.) Не трогайте: по умолчанию `wss://ws-api.oneme.ru/websocket` |

5. Deploy. Таблицы создаются автоматически (`drizzle-kit push` в startCommand, см. `railway.toml`).
6. Откройте домен Railway → Пульт → **введите номер телефона и код из SMS**.
7. Ваш аккаунт должен состоять в нужной группе MAX. Выберите её в фильтре панели.
8. Напишите Telegram-боту `/start` — и пишите что-нибудь в группе MAX.

## Веб-панель

- статус Telegram-бота и аккаунта MAX (пульс воркера, время синка);
- лента сообщений из MAX в реальном времени;
- список подписчиков (можно удалять);
- включение/выключение пересылки, фильтр группы, тестовая отправка;
- подключение/отключение аккаунта MAX по номеру телефона.

Если задан `ADMIN_SECRET` (рекомендовано), кнопки управления требуют ключ
(вводится один раз, хранится в браузере).

## Локальная разработка

```bash
cp .env.example .env   # укажите TELEGRAM_BOT_TOKEN и DATABASE_URL
npm install
npx drizzle-kit push
npm run dev
```

Без токенов приложение тоже запустится — панель покажет подсказки.

## Структура

- `src/lib/max-ws.ts` — клиент приватного WS-протокола MAX (HELLO/SMS/LOGIN/подписки/история)
- `src/lib/telegram.ts` — клиент Telegram Bot API (long polling, sendMessage)
- `src/lib/bridge/` — воркер моста, рассылка, хранение, статус
- `src/app/api/admin/max/*` — SMS-подключение аккаунта из панели
- `src/instrumentation.ts` — автозапуск воркера при старте сервера
- `src/components/Dashboard.tsx` — пульт управления
